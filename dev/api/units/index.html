Units and loads

The field reports pathogen load on several bases that are easy to conflate: zoospore equivalents per swab, ITS1 copies per swab, actual zoospores, and sporangia per host. The "10,000 ZE" crash load and the Briggs model's lethal load of 10⁴ sporangia are different quantities. The package gives each basis its own type and converts between them only when the assumptions are stated:

smax  = parameter_load(:briggs2010, :Smax)        # SporangiaPerHost(10000.0)
crash = parameter_load(:kinney2011, :crash_load)  # ZEPerSwab(10000.0)
smax == crash                                     # ArgumentError: different bases

q = parameter_set(:longo2013)                     # 10 to 144 ITS1 copies per zoospore
convert_load(ITS1CopiesPerSwab(5000), ZEPerSwab; copies_per_zoospore = q.copies_per_zoospore_max)

How models use the layer

Model structs keep plain floats, so the ODE right-hand sides are unchanged. The layer is used at the boundaries:

  • Declare the model's time unit. Use Chytridiomycosis.time_unit(::Type{<:MyParameters}) = :day. The published models declare theirs.
  • Read published values into that unit. Use in_time_unit(record, time_unit(MyParameters)) instead of hand-written factors of 365 or
    1. State days_per_year where the paper's year is not 365 days (Schmidt et al. 2017 use
    52 weeks).
  • Type every load a model exposes. Return loads as SporangiaPerHost, ZEPerSwab and so on, and compare model loads with field data only after an explicit convert_load.
  • Turn survival probabilities into hazards with survival_to_hazard, and record the result as a derived (D) value.

Why not Unitful.jl: most of the package's units are domain counts (ZE, ITS1 copies, sporangia, frogs, an arbitrary pool volume) that Unitful does not define and that should never convert into one another implicitly. Time is the only physical dimension the models share. A small internal layer covers both, with no new dependency.

Loads

Chytridiomycosis.PathogenLoad — Type
PathogenLoad

Supertype of the four load types: ZEPerSwab, ITS1CopiesPerSwab, Zoospores and SporangiaPerHost. Each stores log10 of the value, so loads spanning many orders of magnitude keep their precision.

  • Construct a load from the natural value, for example ZEPerSwab(1e4), or from log10 with ZEPerSwab(; log10 = 4).
  • Read it back with load_value or log10(x).
  • Loads of the same type compare (<, ==, isapprox). Comparing loads of different types throws an ArgumentError, because there is no basis to compare them on.
  • Change basis only with convert_load, which takes the assumptions as keyword arguments.

Chytridiomycosis.ZEPerSwab — Type
ZEPerSwab(value)
ZEPerSwab(; log10)

Zoospore equivalents per swab. This is the qPCR estimate, scaled against standards made from counted zoospores of one Bd strain. It is the unit of most field data and of the "10,000 ZE" crash load.

source
Chytridiomycosis.ITS1CopiesPerSwab — Type
ITS1CopiesPerSwab(value)
ITS1CopiesPerSwab(; log10)

ITS1 gene copies per swab, from qPCR scaled against amplicon standards. The number of copies per zoospore varies among Bd strains (Longo et al. 2013), so converting to ZEPerSwab needs copies_per_zoospore.

source
Chytridiomycosis.Zoospores — Type
Zoospores(value)
Zoospores(; log10)

A count of actual zoospores, such as zoospores on one host, in a culture well or in the pool of the Briggs model. The compartment it counts is the model's to state. It is not the qPCR-based ZEPerSwab.

source
Chytridiomycosis.SporangiaPerHost — Type
SporangiaPerHost(value)
SporangiaPerHost(; log10)

Sporangia (zoosporangia) on one host. This is the state variable of the Briggs et al. (2010) load model, whose lethal load Smax is in these units. Converting it to or from ZEPerSwab has no published basis.

source
Chytridiomycosis.load_value — Function
load_value(x::PathogenLoad) -> Float64

The natural-scale value of load x, in the units of its type. log10(x) gives log10 of the value.

source
Chytridiomycosis.convert_load — Function
convert_load(x::PathogenLoad, ::Type{<:PathogenLoad}; assumptions...)

Convert load x to another basis. Every assumption the conversion rests on is a required keyword argument, so it is visible at the call site. Conversions are exact inverses of each other.

from → tokeywordsrule
ITS1CopiesPerSwab ↔ ZEPerSwabcopies_per_zoospore, extraction_factor = 1ZE = copies × extraction_factor / copies_per_zoospore
ZEPerSwab ↔ Zoosporesswab_fractionzoospores on the host = ZE / swab_fraction
ZEPerSwab ↔ SporangiaPerHostze_per_sporangiumsporangia = ZE / ze_per_sporangium; warns
  • copies_per_zoospore is the ITS1 copy number of the strain used for the standards. It ranges from 10 to 144 among strains (parameter_set(:longo2013)).
  • extraction_factor carries any protocol rescaling between labs, such as dilution of the extract.
  • swab_fraction is the fraction of the zoospores on a host that one swab recovers.
  • ZE to sporangia has no published basis (review §2.4). That conversion exists so a model can state its assumption, and it warns each time it is called.

Converting to the same type returns x. Other pairs throw an ArgumentError; go through ZEPerSwab in two explicit steps.

source
Chytridiomycosis.parameter_load — Function
parameter_load(key::Symbol, symbol::Symbol; set = "") -> PathogenLoad

The compendium value symbol of source paper key, typed by the load basis its units name. Recognised units are "ZE swab^-1", "ITS1 copies swab^-1", "zoospores" and "sporangia host^-1". Throws an ArgumentError if the record is not a load.

For example, parameter_load(:briggs2010, :Smax) is a SporangiaPerHost and parameter_load(:kinney2011, :crash_load) is a ZEPerSwab. They cannot be compared without an explicit conversion.

Time units

Chytridiomycosis.convert_rate — Function
convert_rate(r, (from => to)::Pair{Symbol,Symbol}; days_per_year = 365)

Convert a rate r per from into a rate per to. Time units are :hour, :day, :week and :year. A year is days_per_year days.

The default year is 365 days. Pass the source paper's own convention when it differs. For example, Schmidt et al. (2017) use 52 weeks (364 days): their e = 364 yr⁻¹ is one day.

convert_rate(52.0, :year => :day; days_per_year = 364)   # 1/7 per day
source
Chytridiomycosis.in_time_unit — Function
in_time_unit(r::ParameterRecord, to::Symbol; days_per_year = 365) -> Float64

The value of compendium record r with its time component expressed in to (:hour, :day, :week or :year). It reads the time unit from the record's units:

  • a rate ("yr^-1", "ha yr^-1", "zoospore^-1 yr^-1") is converted as a rate;
  • a duration ("day") is converted as a time.

Other unit factors are left as they are. Throws an ArgumentError when the units contain no time unit. Use it at the boundary where a model reads a published value into its own time unit (time_unit).

source
Chytridiomycosis.survival_to_hazard — Function
survival_to_hazard(p, Δt)

The constant hazard rate (per unit of Δt) that gives survival probability p over an interval Δt: −log(p)/Δt. A hazard computed this way from a published survival is a derived (D) value, and its compendium record should say so in notes.

source
Chytridiomycosis.hazard_to_survival — Function
hazard_to_survival(h, Δt)

The probability of surviving an interval Δt at constant hazard h: exp(−hΔt). It is the inverse of survival_to_hazard.

source
Chytridiomycosis.time_unit — Function
time_unit(p) -> Symbol
time_unit(::Type)

The time unit in which a model's parameter struct holds its rates: :hour, :day, :week or :year. Declared so far:

  • SchmidtParameters: :year
  • BriggsParameters and BriggsSeasonalParameters: :day
  • MitchellParameters: :year
  • WoodhamsParameters: :hour
  • RumschlagParameters: :day
  • RefugiaParameters: :week
  • BozzutoParameters: :year
  • MalagonParameters and TomprosParameters: :day
  • DrawertParameters: :day
  • ChowdhuryParameters: :day

A new model declares its own with Chytridiomycosis.time_unit(::Type{<:MyParameters}) = :day.
